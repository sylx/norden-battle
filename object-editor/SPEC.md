# object-editor 仕様

## 背景
- map-editor の人工物（村・城・砦・橋）は `render/structures/` で box / cone / roof をコードで組み、模様をシェーダで描いている。そのため「作り物っぽさ」が残り、バリエーションも少ない。
- これから描くユニットには、ある程度のディテールと、リグ付きのスケルタルアニメーションが要る。
- ユーザーは Blender を使えない。それでも Mixamo などのアニメーションを組み合わせたい。
- 決まっていること: ユニットは **1 HEX に数体〜十数体の小部隊**。画風は **ミニチュア／ジオラマ風**。

## 方針（2026-09-29 改訂）
当初は「外部素材を集めて整えて組む」方針だった。しかし、部隊で数百体を描くには素材もローポリにせざるを得ず、それならコードで生成しても見劣りしないと判断した。試作（`asset-runtime/src/three/soldier/`）で、戦闘カメラの距離なら十分使えることを確かめた。

| 対象 | 形 | 動き |
|---|---|---|
| **ユニット** | **プロシージャル生成**。Mixamo 骨格の各骨にコードで作ったパーツを固定する | **Mixamo** のモーションを取り込んでそのまま使う |
| **建物** | 配置は今の手続き生成のまま（地形に沿う・道を避ける・城壁がつながる）。形をコードで作り込むか、取り込んだ部品に差し替えるかは未決 | — |
| **指揮官などの近景用** | 必要なら取り込んだキャラ（Mixamo のキャラなど）を使う | Mixamo |

ディテールは素材ではなく、パーツの設計（シルエット・プロポーション・配色）で出す。プロシージャル感を消すのに必要なのはポリ数ではなく、この設計の手間である。

### object-editor の役割
1. **アニメーションの取り込み口**: Mixamo の FBX を取り込み、骨の名前をそろえてカタログに登録する（実装済み）。
2. **生成器の調整場**: 兵士（兵種）・建物の生成パラメータを GUI で動かし、バリエーションを戦闘カメラの距離で見比べる。
3. **素材の取り込み**: 建物の部品や近景用のキャラが必要になったときに使う（実装済み）。

## ユニットの仕組み
- **骨格**: Mixamo 標準の骨格（骨の名前は `mixamorigHips` の形）。取り込んだキャラかモーションの基準姿勢（T ポーズ）から骨だけを取り出して雛形にする（`createSkeletonTemplate`）。
- **パーツ**: 胴・手足・頭・兜・鎧・武器・盾をコードで作り、それぞれ 1 本の骨に重み 1 で固定する。肌の変形がないので形が破綻しない。
  - 寸法は骨格から測る（身長 170 に対する単位 u。Mixamo なら 1u ≒ 1cm）。
  - 基準の向き: 体の正面は +Z、左は +X、T ポーズで手のひらは下。武器の柄と盾の向きはこれを前提に決める。
- **まとめ方**: 全パーツを頂点カラー＋フラットシェーディングの 1 つの SkinnedMesh にまとめる。1 体は約 1,000 三角形、1 ドローコール。
- **大きさ**: 身長 0.1（hexSize = 1）にデフォルメする。頭は大きめ（既定は 1.3 倍）。
- **動き**: Mixamo のクリップをそのまま再生する。骨の名前がそろっているので、どのモーションもどの兵士にも当たる。
- **パラメータ**（`SoldierParams`）: 兜・鎧・武器・盾・チーム色・頭の大きさ・太さ・個体差のシード。個体差のシードで肌・髪・ズボンの色やひげが変わる。

## データモデル（`assets/catalog/`）
| 種類 | 状態 | 内容 |
|---|---|---|
| **Source** | 実装済み | 取り込んだ元ファイル。出典・ライセンス・正規化の変換（rotation / pivot / scale）・統計 |
| **AnimClip** | 未実装 | Source のクリップの編集結果。トリム、ループ、その場化、速度、イベント（攻撃が当たる・矢を放つ・倒れきった）、ボーンマスク（上半身・下半身） |
| **UnitType**（兵種） | 未実装 | SoldierParams の装備の候補と、**ステート → クリップの対応**（idle / march / attack / hit / die / victory。それぞれ複数の候補を持てる）、部隊の設定 |
| **SquadLayout** | 未実装 | 人数ごとの隊形（HEX 内の並び）、個体差の幅、HP に応じて人数を減らす規則 |
| **Prefab**（建物） | 未決 | 建物を部品の差し替えにする場合だけ作る。部品の配置、バリアント規則、フットプリント、接続ソケット |

ID で相互に参照する。map-editor のマップ JSON の形式は変えない。

## 機能一覧

### A. 取り込み・正規化（実装済み）
- GLB / glTF / FBX / OBJ をドロップして取り込む。テクスチャ・.bin・.mtl は一緒にドロップする。ブラウザで GLB に変換する。
- 自動で補正する: 骨の名前の表記ゆれ（`mixamorig:` `mixamorig1:` など）、Mixamo 骨格かどうかの判定、カテゴリごとの目安の高さへの拡大縮小、原点を足元の中心に置く。
- 手で調整する: 90° 単位の回転、原点、高さ（プリセットあり）。
- 出典・ライセンスの入力を必須にする。保存のたびに `assets/CREDITS.md` を作り直す。
- ポリ数・テクスチャの大きさが目安を超えると警告する。

### B. 兵士の試作場（試作済み → 兵種エディタに育てる）
- 実装済み:
  - 装備・チーム色・体格・個体差を切り替えられる。
  - 1 体表示と部隊（12 体）表示を切り替えられる。
  - 取り込んだキャラを横に並べて比較できる。
  - 戦闘カメラの距離から見られる。
- これから:
  - パーツの作り込み: 兜の飾り、袖や裾の段、小物、盾の紋章。
  - 兵種（歩兵・槍兵・弓兵・騎士…）のプリセットを UnitType として保存する。
  - 武器の持ち方をクリップごとに補正する（柄の向き・握る位置）。

### C. アニメーション編集
- クリップの編集: トリム、ループ点、速度、その場化（ルートモーションを捨てる／使う）、左右反転。
- **レイヤーの合成**: 上半身マスクで「歩き（下半身）＋攻撃（上半身）」を作り、新しいクリップとしてベイクする。
- 遷移: ステート間のクロスフェード時間。
- イベント: 攻撃が当たる・矢を放つ・倒れきった、などのフレームに印を付ける。戦闘デモの演出の同期に使う。

### D. 部隊の描画
- 隊形エディタ: 1 HEX 内の並びを人数ごとに定義する（横隊・円陣・散開）。
- 個体差: アニメの開始時刻をずらす、装備の候補から選ぶ、体格を少し変える。
- 描画: 数百体を同時に動かすので、**ボーン行列をテクスチャにベイクし、InstancedMesh でスキニングする**。インスタンスごとにクリップ番号と時刻を渡す。
  - どの頂点も 1 本の骨にしか付いていないので、シェーダは行列 1 つを引くだけで済む。
  - 近景（ユニットを選んで寄ったとき）は普通の SkinnedMesh と AnimationMixer に切り替えられるようにする。

### E. 建物（方針未決）
- 配置の解析は今の `village.ts`・`fortifications.ts` をそのまま使う（辺・頂点・門、道を避ける、`groundRange` で基礎を作る）。
- 形の作り方は次のどちらか。
  - **A. コードで作り込む**: 窓枠・梁・煙突・張り出し・屋根の反り、家の種類を増やす。兵士と同じく、頂点カラー＋フラットシェーディングで画風をそろえる。
  - **B. 部品を差し替える**: 取り込んだモデル（KayKit Medieval Hexagon Pack など）を、辺ごとの城壁・頂点ごとの塔・村の家として置く。
- A で限界を感じてから B に進んでもよい。どちらでも、生成器を object-editor で見比べられるようにする。

### F. ベイク・書き出し
- ボーン行列テクスチャ（兵士の骨格 × クリップ）を書き出す。
- 取り込んだモデルを最適化する（Node 側の `@gltf-transform`。重複の除去、meshopt 圧縮、テクスチャのリサイズ）。
- 兵種のポートレートを自動で撮る（ゲーム UI のユニットアイコンに使う）。

## リポジトリ構成
```
norden-battle/
  assets/
    sources/<id>/        取り込んだ元ファイルと変換した model.glb（Git LFS）
    catalog/sources/     Source の JSON
    CREDITS.md           カタログから自動生成
  asset-runtime/         カタログの型（three.js 非依存）と three.js 側
    src/three/soldier/   プロシージャル兵士（builder.ts: 骨に固定するメッシュの組み立て、soldier.ts: 兵士の形）
  object-editor/
    server/vite-plugin-assets.ts  開発サーバーの API（カタログの読み書き、ファイル保存）
    src/import/          取り込み
    src/lab/             兵士の試作場
    src/editor/          状態と UI
  map-editor/
```

## 段階的な実装
1. **P0 土台**（完了）: npm workspaces、`assets/` と Git LFS、asset-runtime、取り込み・正規化・カタログ保存。
2. **兵士の試作**（完了）: Mixamo 骨格にパーツを固定する兵士、試作場。
3. **P1 兵種**: パーツの作り込み、兵種プリセット（UnitType）の保存、武器の持ち方の補正。弓兵・騎士（下馬）まで。
4. **P2 アニメーション**: クリップ編集、ステート → クリップの対応、イベント、レイヤー合成。
5. **P3 部隊**: ボーン行列のベイク、インスタンス描画、隊形と個体差。地形の上に数百体を置いて負荷を測る。
6. **P4 建物**: 方針 A / B を決めて、村・城・砦・橋を作り直す。
7. **P5 騎兵**: 馬の骨格とモーションの入手、馬のパーツ。

## リスク・未決事項
- **武器の持ち方**: 柄の向きは T ポーズの手の向きから決めている。モーションによっては不自然になるので、クリップごとの補正が要るかもしれない。
- **Mixamo のモーションの種類**: 槍・弓・盾を使うモーションは少ない。剣と盾のモーションを流用するか、レイヤー合成で補う。
- **騎兵（四足）**: Mixamo では扱えない。アニメーション付きの馬が入った CC0 パックを使うか、AI サービスの四足リグを使う。そのため、骨格の種類を `mixamo` 固定にはしない。
- **プロシージャル感**: 形を変えられるパラメータが少ないと、どの兵士も同じに見える。兵種ごとにシルエットがはっきり違うこと（兜・武器・盾・マント）を優先する。
- **ライセンス**: Mixamo の素材も有料アセットも、素材そのものは再配布できない。`assets/sources` を公開リポジトリに置くかどうかを決める必要がある（今は取り込んだ素材をコミットしていない）。
