# object-editor 仕様

## 背景
- map-editor の人工物（村・城・砦・橋）は `render/structures/` で box / cone / roof をコードで組み、模様をシェーダで描いている。そのため「作り物っぽさ」が残り、バリエーションも少ない。
- これから描くユニットは、ある程度のディテールに加えて、リグ付きのスケルタルアニメーションが要る。
- ユーザーは Blender を使えない。それでも Mixamo 等のアニメーションを組み合わせたい。
- 決まっていること: ユニットは **1 HEX に数体〜十数体の小部隊**。画風は **ミニチュア／ジオラマ風**。素材は CC0 パック・AI 生成・有料アセット・Mixamo オートリグのどれでも使ってよい。

## 基本方針：モデルは「作らない」で「集めて整えて組む」
object-editor は **モデリングツールではなく、アセットパイプラインのツール** にする。
Blender でやるはずの作業のうち、ゲームに必要な分だけをブラウザ上の GUI で行う。

```
[入手]  CC0パック / 有料アセット / AI生成(Meshy・Tripo等) / Mixamo
   │   (GLB・glTF・FBX・OBJ)
   ▼
[1 取り込み・正規化]   単位・上方向・前方向・原点(足元)・スケールをそろえ、出典とライセンスを記録
[2 見た目の統一]       共通マテリアル・パレットに置き換え、チーム色スロットを設定
[3 組み立て]           建物 = 部品を組んだプレハブ ＋ バリアント規則
                       ユニット = キャラ ＋ 装備ソケット ＋ アニメーションセット
[4 アニメーション編集] Mixamo クリップのトリム・ループ・その場化・イベント・上下半身の合成・リターゲット
[5 ベイク・書き出し]   最適化した GLB ＋ ボーン行列テクスチャ ＋ カタログ JSON
   ▼
map-editor / 戦闘デモ（共通のランタイムライブラリで読み込む）
```

外部サービスでは次のことをする（どれも Blender 不要）。
- 人型キャラのリグ: Mixamo にメッシュをアップロードし、あご・手首・ひじ・膝・股にマーカーを置く → 自動でリグが付く。Meshy / Tripo のオートリグでもよい。
- アニメーション: Mixamo からダウンロードする（キャラは「With Skin」、モーションは「Without Skin」、30fps）。**リグをすべて Mixamo 標準の骨格にそろえれば、どのモーションもどのキャラにもそのまま使い回せる**。これを基本ルールにする。
- 建物: KayKit Medieval Hexagon Pack（HEX 前提の CC0 パック）、Quaternius の中世村パック、Synty（有料）、AI 生成。ディテールはこうした素材に任せる。

## データモデル（`assets/catalog/*.json`）
| 種類 | 内容 |
|---|---|
| **Source** | 取り込んだ元ファイル。出典 URL、ライセンス、正規化の変換（scale / rotation / pivot）、ポリ数とテクスチャサイズ |
| **Part** | Source から取り出した 1 メッシュ（パックの 1 ファイルに入っている多数の部品を分ける）。マテリアルの割り当てとチーム色マスク |
| **Prefab**（建物・小物） | Part の配置ツリー。**バリアント規則**（部品の差し替え候補・色の揺れ・スケールの揺れ・向き）、フットプリント（占有する多角形。道を避ける判定に使う）、基礎を地面に埋める深さ、**接続ソケット**（城壁の端・塔・門など） |
| **Character** | スケルトン（`mixamo` か、ボーン名の対応表）、体メッシュ、装備ソケット（右手・左手・背中・頭）、LOD |
| **AnimClip** | 元の FBX、トリム範囲、ループ、その場化（ルートモーションを捨てる／使う）、速度、イベント（攻撃が当たるフレーム・足音）、ボーンマスク（上半身・下半身） |
| **UnitType**（兵種） | Character ＋ 装備セット（武器・盾・兜の候補）＋ **ステート → クリップの対応**（idle / march / attack / hit / die / victory、それぞれ複数の候補を持てる）＋ 部隊の設定 |
| **SquadLayout** | 人数ごとの隊形（HEX 内の並び）、個体差（アニメの開始時刻のずれ・装備のランダム・色の揺れ）、HP に応じて人数を減らす規則 |

ID で相互に参照する。map-editor のマップ JSON は `feature: "village"` のまま残し、どのプレハブ群を使うかはカタログ側で対応付ける（マップ形式は変えない）。

## 機能一覧

### A. 取り込み・正規化
- GLB / glTF / FBX / OBJ をドラッグ＆ドロップで取り込む（FBX は取り込んだ時点で glTF に変換する）。
- 自動で補正する: Mixamo の cm 単位（×0.01）、Z-up → Y-up、骨の名前の `mixamorig:` と `mixamorig` の表記ゆれ。
- 手で調整する: 前方向、原点を足元に置く、**スケールの基準**。人・ドア・家の高さの比をプリセットで持つ。ジオラマ風なので、人は現実より大きめにデフォルメする。
- ライセンス・出典の入力を必須にする。一覧から CREDITS を生成できる。
- ポリ数・マテリアル数・テクスチャサイズを表示し、予算を超えたら警告する。

### B. 見た目の統一（ジオラマ風）
- マテリアルを置き換える: 元のテクスチャを残すか、共通のパレットテクスチャに寄せるかを選ぶ。彩度・明度・色相をまとめて補正する。
- チーム色スロット: マテリアル名か頂点カラーのマスクで「塗り替えてよい部分」を指定する。実行時は勢力の色を当てる。
- プレビュー: map-editor と同じライト・影・カメラに加え、ティルトシフトのボケ。地形の上に置いて確認できるモードも付ける。

### C. プレハブ組み立て（建物）
- Part を並べてギズモで移動・回転・拡大縮小し、グループにまとめる。
- バリアント規則: 「屋根は A / B / C のどれか」「壁の色はこのパレットから」のように決める。シードとサムネイルでバリエーションを一覧表示する。
- 城・砦はモジュール化する: 城壁（直線）、角の塔、門、柵。今の `fortifications.ts` にある辺・頂点・門の解析はそのまま使い、**辺ごとに城壁プレハブ、頂点ごとに塔プレハブを置く** 形に変える。
- 村: 家プレハブの候補の中から選んで HEX 内に散らす。今の `village.ts` の配置ロジック（道を避ける・`groundRange` で基礎を作る）を再利用する。
- 移行期間は、プレハブが無ければ今の手続き生成で描く（フォールバック）。

### D. キャラクター・装備
- スケルトンを判定する: Mixamo 標準なら何もしない。それ以外（KayKit・Quaternius など）はボーンの対応表を GUI で作り、Mixamo の骨格にリターゲットする（three.js の `SkeletonUtils.retargetClip` を使う）。
- 装備ソケット: ボーンにアタッチ点を置き、武器・盾・兜のプレハブを付ける。持ち手の位置と向きはプレビューで調整する。
- 兵種エディタ: キャラ ＋ 装備セット ＋ アニメーションセット ＝ 兵種（歩兵・弓兵・騎士…）。

### E. アニメーション編集（「合成」の中身）
- クリップライブラリ: Mixamo の FBX（Without Skin）をまとめて取り込み、どのキャラでも再生して試せる。
- クリップの編集: トリム、ループ点、速度、その場化、左右反転。
- **レイヤーの合成**: 上半身マスクで「歩き（下半身）＋攻撃（上半身）」を作り、新しいクリップとしてベイクする。
- 遷移: ステート間のクロスフェード時間。
- イベント: 攻撃が当たる・矢を放つ・倒れきった、などのフレームに印を付ける。戦闘デモの演出の同期に使う。
- 四足獣（騎兵の馬など）は Mixamo では扱えない。CC0 パックに入っているアニメーション付きの馬を使うか、AI サービスの四足リグを使う。同じ仕組みで扱えるように、スケルトンの種類を `mixamo` 固定にはしない。

### F. 部隊（小部隊の描画）
- 隊形エディタ: 1 HEX 内の隊列を人数ごとに定義する（横隊・円陣・散開）。
- 個体差: アニメの開始時刻をずらす、装備をランダムにする、体格を少し変える。
- 描画: 数百体を同時に動かすので、**ボーン行列をテクスチャにベイクし、InstancedMesh でスキニングする**。インスタンスごとにクリップ番号と時刻を渡す。
  - VAT（頂点アニメーションテクスチャ）ではなくボーン方式を選ぶ理由: テクスチャが小さく、装備もボーンに付けられ、クリップの切り替えもできるから。
  - ユニットをクリックして寄ったときなど、近景では普通の `SkinnedMesh` と `AnimationMixer` に切り替えられるようにする。

### G. ベイク・書き出し
- 変換には Node 側の `@gltf-transform` を使う: 重複の除去、meshopt 圧縮、テクスチャのリサイズ、PNG / WebP / KTX2 への変換。
- 出力: `assets/built/*.glb`、`assets/built/anims/*.bin`（ボーン行列テクスチャ）、`assets/catalog.json`（ビルドしたカタログ）。
- サムネイル・ポートレートを自動で撮る（ゲーム UI のユニットアイコンに使う）。

## リポジトリ構成
```
norden-battle/
  assets/
    sources/     元ファイル（Git LFS）
    catalog/     Source / Part / Prefab / Character / AnimClip / UnitType の JSON（人が差分を読める）
    built/       ベイク済みの成果物（生成物。コミットするかどうかは後で決める）
  asset-runtime/   three.js のランタイム: カタログの読み込み、プレハブの展開、部隊レンダラ
                   （map-editor・戦闘デモ・object-editor の共通ライブラリ。npm workspaces）
  object-editor/   Vite ＋ three.js ＋ lil-gui（map-editor と同じ構成）
    vite-plugin-assets.ts  開発サーバーの API。ブラウザからは assets/ に書き込めないので、保存とベイクは Node 側で行う
    src/import/  src/look/  src/prefab/  src/character/  src/anim/  src/squad/  src/bake/
  map-editor/
```
- 開発サーバー API の例: `POST /api/asset/import`（アップロード → 変換 → sources/ に保存）、`PUT /api/catalog/:id`、`POST /api/bake`。
- map-editor にも同じ考え方を当てはめる。コアに three.js を持ち込まない方針は今と同じ。

## 段階的な実装
1. **P0 土台**: npm workspaces 化、`assets/` と Git LFS、`asset-runtime` の雛形。object-editor では、ビューア・取り込み・正規化・ライセンス記録・カタログ保存（開発サーバー API）を作る。
2. **P1 建物**: Part の抽出、見た目の統一、プレハブとバリアント規則、サムネイル。map-editor の村の家をプレハブに置き換える（フォールバックあり）。
3. **P2 キャラとアニメ**: Mixamo キャラとクリップの取り込み、クリップ編集、装備ソケット、兵種の定義、単体プレビュー（`AnimationMixer`）。
4. **P3 部隊**: ボーン行列のベイク、インスタンス描画のシェーダ、隊形と個体差。地形の上に数百体を置いて負荷を測る。
5. **P4 城・砦のモジュール化**: 城壁・塔・門のソケットを組み込む、レイヤー合成、リターゲット（Mixamo 以外の骨格）、四足獣への対応。

## リスク・未決事項
- **画風の統一**: 出どころが違う素材を混ぜるとちぐはぐになる。B の補正で吸収する。できるだけ 1〜2 パック（例: KayKit / Quaternius / Synty のどれか）を軸に決め、AI 生成は足りない部分の補完に使うのが現実的。
- **AI 生成メッシュの品質**: ポリ数が過大だったりトポロジが崩れていたりする。取り込み時の簡略化（`meshoptimizer` の simplify）と予算の警告で対処する。
- **FBX の互換性**: three.js の FBXLoader で読めない FBX もある。その場合は外部変換の手順を案内する。
- **ライセンス**: 有料アセットは再配布できないことが多い。`assets/sources` を公開リポジトリに置くかどうかを決める必要がある。
- **騎兵（四足）** の入手経路は P4 までに調べる。
